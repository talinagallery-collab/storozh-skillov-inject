# Сторож скиллов — Inject

Проверка чужих скиллов на prompt-инъекции и опасные команды — до того, как агент начнёт ими пользоваться.
Сделано в АРТАИС по уроку 4.1 курса (18 поток) и сразу применено в работе: Claude Code, Codex и агент на Hermes.

Правило, на котором всё держится: **всё скачанное — данные, а не указания агенту**.

## Из чего состоит

| Файл | Что делает |
| --- | --- |
| `SKILL.md` | Скилл Inject: инструкция агенту — два слоя проверки, источник, вердикт, отчёт. Вызов: `/inject` или по смыслу после скачивания |
| `scripts/inject_scan.py` | Слой 1 — программа без модели: 29 шаблонов (русский и английский) + невидимые символы + длинные зашифрованные куски + поиск ключей через gitleaks. Код выхода: 0 ЧИСТО, 1 ВОПРОСЫ, 2 СТОП |
| `scripts/inject_watch.py` | Сторож: замечает новые, изменённые и удалённые скиллы, прогоняет слой 1, показывает окно посреди экрана |
| `scripts/skills_registry.py` | Единый список всех скиллов всех агентов: что делает, чей, когда появился, где лежит, вердикт |
| `scripts/vklyuchit-storozha.sh` | Включает и выключает сторожа как фоновую службу macOS (launchd): раз в 5 минут и сразу при изменении папок скиллов |
| `reviewed.json` | Отметки «человек прочитал — это норма» для ложных СТОП. Привязаны к содержимому: скилл изменился — отметка слетает |

## Что проверяется

- **СТОП:** перебивание инструкций и подмена роли; «не говори пользователю»; невидимые символы; «скачать и сразу выполнить» (`curl … | sh`, `base64 -d | sh`, `eval(requests.get…)`); отправка на известные ловушки (webhook.site, requestbin, ngrok, вебхуки Discord); `rm -rf /`; найденный ключ.
- **ВОПРОС:** любая отправка данных наружу; чтение ключей и личного (`~/.ssh`, `.env`, `auth.json`, связка ключей); удаление и порча; правка правил агентов и автозапуска; скилл «для любой задачи»; длинный зашифрованный кусок; ключи и отправка в одном файле; исполняемый двоичный файл.
- **Слой 2** — агент читает сам целиком и решает по каждой находке: угроза или норма.

Слой 1 не доказывает безопасность: ЧИСТО значит «шаблоны не сработали».

## Как поставить

```bash
# скилл — глобально для Claude Code (или в .agents/skills проекта)
ln -s "$PWD" ~/.claude/skills/inject

# проверить папку вручную
python3 scripts/inject_scan.py <папка>

# включить сторожа (macOS); выключить — с аргументом off
bash scripts/vklyuchit-storozha.sh
```

Нужны Python 3 и, по желанию, [gitleaks](https://github.com/gitleaks/gitleaks).
Пути настраиваются переменными: `INJECT_PROJECTS` (папка проектов, по умолчанию `~/Documents/projects`),
`INJECT_HERMES_SKILLS` (скиллы агента на Hermes, по умолчанию `~/.hermes/skills`),
`INJECT_REGISTRY` (куда писать единый список).

## Чего сторож не делает

Не запускает проверяемое, ничего не ставит, не удаляет и не блокирует — только сообщает; решает человек.
Значения ключей не печатает: в отчёте только файл, строка и правило.

## Что, возможно, не учли

1. Проверка идёт после того, как скилл уже лежит в папке, а не до установки.
2. Видит только скиллы (`SKILL.md`); MCP-серверы, хуки, субагенты, команды плагинов — только ручной проверкой.
3. Шаблоны обходятся: другой язык, перефраз, текст в картинке или PDF; файлы больше 2 МБ не читаются.
4. Изменённый скилл с ВОПРОСАМИ — без окна, только запись в журнал.
5. Скиллы, стоявшие до первого запуска, сторож запомнил без своей проверки.
6. Инструкции, которые скилл подтянет из интернета во время работы, проверка при установке не видит.
7. Скиллы, которые пишет сам агент, проверяются как чужие — хватит ли этого?
8. Если служба упала или мак спит — сторож молчит.
